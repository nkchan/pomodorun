# Pomodorun

日本語UIのmacOSメニューバー常駐ポモドーロアプリ。タスク・Brain Dump・Slack Focus Guardをローカル中心に提供します。
Apple Silicon、macOS 13以降向け。サーバー・課金・ライセンス認証はありません。

## 起動

生成したアプリ:

```sh
open src-tauri/target/release/bundle/macos/Pomodorun.app
```

配布場所へ移す場合は `.app` 全体をコピーしてください。Dockには表示されません。メニューバーのトマトを左クリックするとポップアップ、右クリックすると開始／停止・設定・終了メニューが表示されます。
Esc・フォーカス喪失・×は非表示にするだけで、タイマーは継続します。終了はTrayの「終了」から行います。
既定の `Command+Shift+D` はBrain Dumpを開きます。競合する場合は設定で変更してください。

**Developer ID署名・公証はしていません。** 他のMacへコピーした未署名アプリはGatekeeperに止められる場合があります。信頼できるソースであることを確認し、macOSの「プライバシーとセキュリティ」から許可してください。システム全体のGatekeeperを無効化しないでください。
Apple Siliconのリンカーが実行ファイルに付けるad-hoc署名は、Developer ID署名や公証とは異なります。

## 使い方

- 集中25分・短休憩5分・4回ごとの長休憩15分。時間は1〜180分、長休憩間隔は1〜12回まで設定できます。
- 集中の自然完了だけを実績に計上し、休憩は自動開始します。次の集中は手動で開始します。停止・休憩スキップは加算しません。
- 集中開始時のタスクとタイトルを固定します。集中中にタスクを編集・削除してもセッション履歴は残ります。
- タスクの日付を変更して表示・登録できます。表示日より前の未完了タスクは「持ち越し」です。見積もりは1〜99回、実績は完了セッションから集計します。
- Brain Dumpは独立メモとして即保存できます。「今日のタスクにする」は見積もり1のタスクを作成し、メモ本文もDBに保持します。「整理」は論理削除です。
- 通知とサウンドは別々に設定できます。通知をOS側で拒否してもタイマーは動作します。通知が見えない場合はmacOSの通知設定・集中モードも確認してください。Tauriのデスクトップ通知権限APIではOS側の拒否を正確に取得できません。
- 実行中の残り時間はスリープを含む単調時計で計算します。長時間スリープで休憩まで終了した場合は次の集中の待機に戻ります。アプリ再起動では未完了セッションを中断扱いにし、自動再開・実績加算はしません。

## Slack設定

1. [Slack App管理](https://api.slack.com/apps)で専用アプリを用意します。ワークスペースによっては管理者の承認が必要です。
2. OAuth & Permissionsの **User Token Scopes** に次の4つを追加します。
   - `users.profile:read`
   - `users.profile:write`
   - `dnd:read`
   - `dnd:write`
3. ワークスペースへインストール／再インストールし、**User OAuth Token (`xoxp-`)** を取得します。Botトークン(`xoxb-`)は使えません。
4. Pomodorunの設定でトークンを「Keychainに保存」します。入力は成功後に消去され、トークン本体をSQLite・localStorage・ログへ保存しません。
5. 「接続テスト（読取のみ）」を実行します。`auth.test`、`users.profile.get`、`dnd.info` とscopeヘッダーを確認するだけで、ステータス・Snoozeは変更しません。実際の書き込み可否は初回適用で確定します。
6. 「Slack Focus Guard」をオンにして設定を保存します。集中開始で `:tomato:` の集中ステータスとSnoozeを適用します。既存の方が長いSnoozeは変更しません。

休憩・停止・一時停止・終了では元の状態を復元し、再開時はその時点の状態を改めて保存します。
ステータス・Snoozeはそれぞれ現在値を再取得し、アプリの適用値と一致する場合だけ復元します。途中の手動変更は保持します。
期限切れで空になったステータスは手動クリアと区別できないため、自動復元せず設定に「元ステータスを明示復元」を表示します。この操作だけは確認のうえ現在のステータスを上書きします。

通信障害は指数バックオフ＋ジッター（最大60秒）、429はRetry-Afterで再試行します。認証・権限不足は自動再試行を停止します。復元未完了中に次のSlack変更は行いませんが、タイマーは利用できます。
切断・トークン交換は復元完了が先です。失敗時は既存資格情報を保持します。Keychainがロックされた場合は解除して「復元を再試行」してください。
終了時は最大5秒待機し、残ったジャーナルは次回起動で回復します。強制終了・クラッシュでも変更前に記録したジャーナルを使用します。

**制約:** 1ワークスペース・1ユーザー、手動トークン入力のみ。Slack APIには原子的な比較更新がないため、再取得と書き込みの間の競合を完全には防げません。Snoozeは分単位で最大約1分の端数差があります。元の資格情報がKeychainから外部削除された場合は自動回復できません。実Slack試験は専用トークンが提供されていないため未実施です。

## データ保存

```text
~/Library/Application Support/dev.pomodorun.app/pomodorun.sqlite3
```

SQLiteのWAL・SHMファイルも同じディレクトリに作成されます。バックアップはアプリを終了した状態でディレクトリ全体をコピーしてください。
schema `user_version=1`。タスク、セッション、タイマー、メモ、設定、Slack接続メタデータ・復元ジャーナル、MVPの機能フラグを保存します。
復元ジャーナルには元のSlackステータス本文が含まれますが、トークンは含まれません。Keychainのサービス名は `dev.pomodorun.app.slack`、アカウント名は `user-token` です。
削除操作は論理削除です。アプリ削除だけでは保存データ・Keychain資格情報は消えません。Slackを切断・復元してからアンインストールしてください。

## 開発・検証・ビルド

Node 24、npm、Xcode Command Line Tools、Rust stableが必要です。本環境ではRust 1.99をプロジェクト内 `.toolchain/` に配置しています。ラッパーはローカルRustを優先し、ない場合は通常のPATH上のCargoを使います。ユーザー全体のPATHは変更しません。

```sh
npm ci
sh scripts/rust.sh fetch
npm run tauri -- dev
```

検証:

```sh
npm run check
npm audit
sh scripts/rust.sh test
sh scripts/rust.sh clippy --all-targets -- -D warnings
sh scripts/rust.sh fmt --check
```

rustfmt・Clippy未導入の場合は使用中のRust環境で `rustup component add rustfmt clippy` を実行してください。
`scripts/rust.sh` は自身で `src-tauri/` へ移動するため、`--manifest-path src-tauri/Cargo.toml` は付けません。

未署名releaseビルド:

```sh
npm run tauri -- build --bundles app --no-sign
python3 scripts/smoke.py
```

成果物は `src-tauri/target/release/bundle/macos/Pomodorun.app`。
`scripts/smoke.py` はプロセス起動、二重起動、SQLite整合性を確認します。終了はSIGTERMなので、実Slack接続中の通常終了・復元試験には使わないでください。
元の設定のbundle identifierが `.app` で終わるためTauriが命名警告を出しますが、既存データの保存先を維持するため変更していません。
アイコンはオリジナルで `python3 scripts/icons.py` により外部依存なしに再生成できます。

実機確認の推奨手順:
1. `.app` を起動し、Trayの左右クリック、画面端と別ディスプレイでの位置、Esc・フォーカス喪失を確認する。
2. 時間を1分にして通知・サウンドを個別に切り替え、拒否時にもタイマーが継続することを確認する。
3. 集中中にスリープし、集中のみ／休憩も経過したケース、途中で壁時計を変更するケースを確認する。
4. 保存済みショートカットを別アプリで使用して競合表示と旧設定維持を確認する。
5. 専用SlackユーザーでKeychain保存、既存Snooze、手動ステータス変更、オフライン停止、再起動復元を確認する。
